Démonstration

Autocommit contre transaction

Sans transaction
UPDATE demo_salaires SET to_date='2026-11-02'
WHERE emp_no=10001
  AND to_date='9999-01-01';  -- validé
INSERT INTO demo_salaires
VALUES (10001, NULL, ...);   -- ERREUR

-- salaires en cours : 0
Dans une transaction
BEGIN;
UPDATE demo_salaires SET to_date='2026-11-02'
WHERE emp_no=10002
  AND to_date='9999-01-01';
INSERT INTO demo_salaires
VALUES (10002, NULL, ...);   -- ERREUR
ROLLBACK;
-- salaires en cours : 1

Après une erreur, PostgreSQL refuse toute instruction jusqu'au ROLLBACK. SAVEPOINT permet d'annuler une partie seulement.

Verrous

Annoncer ce que l'on va modifier

  • Toute modification verrouille la ligne jusqu'à la fin de la transaction
  • SELECT … FOR UPDATE pose ce verrou dès la lecture
  • Interblocage : détecté après deadlock_timeout (1 s), une transaction est annulée (40P01)
  • Prévention : verrouiller toujours dans le même ordre

Structure d'un bloc

Une fonction PL/pgSQL

CREATE OR REPLACE FUNCTION f_anciennete(p_emp_no integer, p_date date DEFAULT date '2002-08-01')
RETURNS integer LANGUAGE plpgsql STABLE AS $$
DECLARE
    v_embauche date;
BEGIN
    SELECT hire_date INTO v_embauche FROM employees WHERE emp_no = p_emp_no;
    IF NOT FOUND THEN
        RAISE EXCEPTION 'Salarié % inconnu', p_emp_no;
    END IF;
    RETURN extract(year FROM age(p_date, v_embauche))::int;
END $$;

SELECT f_anciennete(10001);   -- 16
Contrôles et erreurs

Une procédure qui refuse les mauvaises saisies

CREATE OR REPLACE PROCEDURE p_renommer_departement(p_dept_no char(4), p_nom varchar)
LANGUAGE plpgsql AS $$
BEGIN
    IF length(trim(p_nom)) < 3 THEN
        RAISE EXCEPTION 'Nom trop court : "%"', p_nom USING ERRCODE = 'invalid_parameter_value';
    END IF;
    UPDATE departments SET dept_name = p_nom WHERE dept_no = p_dept_no;
    IF NOT FOUND THEN
        RAISE EXCEPTION 'Département % inconnu', p_dept_no USING ERRCODE = 'no_data_found';
    END IF;
END $$;

Un ERRCODE explicite permet à l'application de réagir de façon appropriée.

Sécurité

SECURITY DEFINER : deux précautions obligatoires

  • La fonction s'exécute avec les droits de son propriétaire
  • Elle donne accès à une opération précise sans donner accès aux tables
  • 1. Fixer SET search_path = public, pg_temp
  • 2. REVOKE EXECUTE … FROM PUBLIC : par défaut, tout le monde peut exécuter

Triggers

Réagir automatiquement aux écritures

Vocabulaire

Quand et combien de fois ?

TermeSignification
BEFOREavant l'écriture : peut modifier NEW ou annuler (RETURN NULL)
AFTERaprès l'écriture : journaliser, propager ; valeur renvoyée ignorée
FOR EACH ROW / STATEMENTune fois par ligne / une fois par instruction
NEW, OLD, TG_OPligne après, ligne avant, opération
Exemples

Normaliser, puis historiser

BEFORE INSERT OR UPDATE
CREATE FUNCTION f_normaliser_nom_dept()
RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN
  NEW.dept_name := initcap(trim(NEW.dept_name));
  RETURN NEW;
END $$;
AFTER UPDATE
CREATE FUNCTION f_historiser_dept()
RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN
  IF NEW.dept_name IS DISTINCT FROM OLD.dept_name THEN
    INSERT INTO historique_departements
      (dept_no, ancien_nom, nouveau_nom)
    VALUES (OLD.dept_no, OLD.dept_name, NEW.dept_name);
  END IF;
  RETURN NULL;
END $$;

Résultat : « service client » devient « Service Client », et l'historique note « Customer Service → Service Client » avec l'auteur.

Bonnes pratiques

Contrainte d'abord, trigger ensuite

  • CHECK, UNIQUE, clé étrangère, exclusion : plus simples, plus rapides, impossibles à oublier
  • Trigger : règles qui consultent d'autres lignes, et audit
  • FOR EACH ROW sur des millions de lignes : un coût visible
  • session_user = la personne connectée ; current_user change dans SECURITY DEFINER
PARTIE 4

Utilisateurs et droits

Le moindre privilège

Rôles

Un groupe, un compte, un droit

CREATE ROLE communication NOLOGIN;                     -- un groupe
GRANT USAGE ON SCHEMA public TO communication;
GRANT SELECT ON departments TO communication;
CREATE ROLE dora LOGIN PASSWORD 'dora-demo' IN ROLE communication;

SET ROLE dora;
SELECT count(*) FROM departments;   -- 9
SELECT count(*) FROM employees;     -- ERROR: permission denied for table employees
RESET ROLE;

Droits par colonne : GRANT SELECT (col1, col2) ON t TO r. Sous-ensemble : une vue.

Droits par défaut

Trois points à connaître

  • Depuis PostgreSQL 15, PUBLIC ne crée plus d'objets dans le schéma public
  • PUBLIC n'a aucun droit sur les tables, mais exécute toutes les fonctions par défaut
  • Vue : les tables sont lues avec les droits du propriétaire ; les fonctions avec ceux de l'appelant
  • Aperçu : Row-Level Security filtre les lignes selon l'utilisateur
